# Порядок коллективной работы

Учебный процесс: **Issue → feature-ветка → коммиты → Pull Request → проверка → merge → закрытие Issue**.

Ветки:
- `feature/data-collection`: исходный Unity-лог, код сбора, словарь полей;
- `feature/analysis`: расчёт метрик, тесты, интерпретация;
- `feature/documentation`: README, CONTRIBUTING, отчёт.

Предлагаемая канбан-доска GitHub Projects: `To Do`, `In Progress`, `Review`, `Done`. Соответствующие Issues — #1–#6.

Требования к проверке: сверить схему CSV, расчёт средних и выборочного стандартного отклонения, правило 1,5 IQR; убедиться, что пропуски `reaction_time` для `miss` и `move` не трактуются как нули; проверить отсутствие персональных данных.

**Состав команды:** один владелец репозитория. В настоящее время независимое code review второго участника не проведено. Ревью-замечания автора фиксируются как собственная проверка. При подключении второго участника он может провести полноценный review через GitHub.

**GitHub Projects, Wiki, Discussions:** материалы для Wiki подготовлены в `docs/wiki/`. Если не созданы как отдельные сущности GitHub, их наличие в папке нельзя считать подтверждением выполнения этих функций.
