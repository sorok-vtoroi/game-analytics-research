# Правила участия в исследовании

1. Перед изменениями создайте Issue, кратко сформулируйте задачу и критерии готовности.
2. Создайте ветку `feature/<topic>` от актуальной `main`. Не вносите экспериментальные изменения непосредственно в `main`.
3. В одном PR решайте одну логическую задачу; в описании укажите цель, изменения, ссылку на Issue, результат проверки и ограничения.
4. Пишите небольшие осмысленные коммиты (`data:`, `analysis:`, `docs:`, `test:`).
5. Не переписывайте `data/raw` после фиксации источника; производные файлы создавайте скриптами.
6. Перед PR запустите `python -m unittest discover -s tests`, проверьте корректность подсчёта и отсутствие персональных данных, ключей и токенов.
7. Независимое review выполняет другой участник при наличии команды. Если работа выполняется единственным участником, документируйте собственную проверку явно как self-review; не выдавайте её за независимое одобрение.
8. После проверки обновите ветку относительно `main`, устраните замечания и объедините PR; Issue закройте после выполнения критериев.

## Требования к данным

Публичная публикация допускает только обезличенные данные и файлы, на которые есть право публикации. Для больших бинарных файлов используйте Git LFS. Проверки воспроизводимости должны отличать реальные экспериментальные данные от синтетических.
